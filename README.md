# EinsteinAI

**EinsteinAI** is a web-based physics tutor. It combines a React and Vite client, a FastAPI service, a LangChain agent powered by Google Gemini, and Supabase for authentication, conversation storage, and account usage.

This repository is a local-development project. The guide below documents the current implementation and its manual plan management; it does not imply that payments or production hosting are configured.

## Product capabilities

- Account registration, sign-in, sign-out, and editable display name through Supabase Auth.
- Physics-focused answers generated by a LangChain agent using Google Gemini.
- Optional step-by-step solutions for physics problems.
- Conversation history saved to Supabase, with conversation search, pinning, and deletion.
- Message search within a conversation; copy answers; export as text or print/save as PDF.
- Edit and resend a user question. The edited question replaces the original and removes later messages in that conversation before receiving a new answer.
- Suggested follow-up prompts to continue exploring a topic.
- Profile page with plan status, expiry, question balance, and model token usage.
- Manually administered access: two free questions per account, a 10-question pack, or unlimited monthly/yearly subscriptions. There is no payment checkout.

## Architecture at a glance

```text
React browser app
   ├── Supabase Auth ─────────────── user identity and session
   ├── Supabase database ─────────── profile, conversations, messages, usage
   └── FastAPI backend ───────────── bearer-token verification and quota enforcement
          ├── LangChain agent ────── conversation context and calculator tool
          └── Google Gemini ──────── physics answer generation
```

The browser sends its Supabase access token to the backend. The backend validates that token, applies the user's allowance through server-only database functions, calls Gemini, and returns the answer and usage data. The Supabase service-role key and Gemini key stay on the backend.

## Quick start

### 1. Prerequisites

- Python 3.10 or newer (the repository's existing virtual environment may use a newer version).
- Node.js and npm.
- A Supabase project with the SQL migrations applied.
- A Google Gemini API key.

### 2. Configure Supabase

In Supabase Dashboard → **SQL Editor**, run the included scripts in this order:

1. [`supabase/subscription_usage.sql`](supabase/subscription_usage.sql)
2. [`supabase/manual_plans_setup.sql`](supabase/manual_plans_setup.sql)
3. [`supabase/chat_features.sql`](supabase/chat_features.sql)

These files create account usage, plan handling, quota/token functions, and pinned-conversation support. They do not create the `conversations` and `messages` tables. If your Supabase project does not already have those tables, first follow the reference setup at the beginning of [Database and plan administration](docs/DATABASE.md), then run the scripts above. That guide also explains table behavior and plan assignment.

### 3. Configure local environment files

Create `backend/.env` from [`backend/.env.example`](backend/.env.example):

```dotenv
GEMINI_API_KEY=your_gemini_api_key
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_PUBLISHABLE_KEY=your_supabase_publishable_key
SUPABASE_SERVICE_ROLE_KEY=your_supabase_service_role_key
CORS_ORIGINS=http://localhost:5173,http://localhost:5174
```

Create `frontend/.env`:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your_supabase_publishable_key
VITE_API_URL=http://localhost:8000
```

Use the URL and keys from the same Supabase project. The publishable key is used by the browser; the service-role key is backend-only. Never add Gemini or service-role credentials to `frontend/.env`, commit `.env` files, or paste secrets into issues or screenshots. Vite environment values are compiled into client-side code and must be treated as public.

### 4. Start the backend and frontend

Start the backend in one terminal from the repository root:

```bash
cd backend
../.venv/bin/python -m pip install -r requirements.txt
../.venv/bin/python -m uvicorn main:app --reload --port 8000
```

Start the frontend in another terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the URL printed by Vite (normally [http://localhost:5173](http://localhost:5173)). If that port is busy, Vite may use 5174. The included backend CORS defaults allow both ports.

Check backend availability at [http://localhost:8000/health](http://localhost:8000/health). The interactive API documentation is available at [http://localhost:8000/docs](http://localhost:8000/docs).

## Current plan rules

| Plan | Current behavior |
|---|---|
| Free | Two free questions per account, subject to the usage-counter behavior described in [Database and plan administration](docs/DATABASE.md#question-allowance-behavior). |
| 10-question pack | Adds 10 credits; credits expire at the next midnight in Asia/Kolkata. |
| Monthly | Unlimited questions while active; expiry is one month from manual assignment. |
| Yearly | Unlimited questions while active; expiry is one year from manual assignment. |

An account administrator changes a plan directly in `public.account_usage` using Supabase SQL Editor. The database trigger sets plan status and expiry. Reassigning `monthly` or `yearly` restarts the term from the new assignment time. Assigning `questions_10` adds 10 credits to any unexpired credits. See [Database and plan administration](docs/DATABASE.md).

## Known operational boundaries

- Payments, checkout, invoices, and automatic renewals are not implemented.
- The backend currently allows localhost Vite origins by default. A hosted frontend requires updating the backend CORS allowlist and environment configuration.
- The app displays Gemini token usage when the model response includes usage metadata; a missing count may be recorded as zero.
- The app is designed for development and demonstration. Review the deployment and security checklist before exposing it publicly.

## Deployment files

- `render.yaml` defines the Render API service and its health check.
- `frontend/vercel.json` configures the Vercel single-page-app fallback.
- `backend/.env.example` and `frontend/.env.example` show the required variable names without real credentials.
